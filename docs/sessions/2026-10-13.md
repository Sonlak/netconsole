### 08:55 -- Fix NetBox URL join bug + add contains/prefix filters

**Context**: deploy #591 vừa xong thì user test live:
- `192.168.95.0` → `list_netbox_prefixes` → "không tìm thấy" ✓ (đúng, không có)
- `10.10.20.0/24` → `list_netbox_prefixes` → "không tìm thấy" (đúng, sync chưa tạo)
- "thiết bị trên netbox kìa" → 502: `Unexpected token '<', "<!DOCTYPE "..."`

**Bug #1 (CRITICAL)**: `new URL('/dcim/devices/', 'http://host:8080/api/')`
WHATWG URL spec treat path bắt đầu bằng `/` là absolute → REPLACE base path.
Kết quả: `http://host:8080/dcim/devices/` (mất `/api/`) → trỏ vào NetBox
404 HTML page. `fetch` đọc HTML, `response.json()` throws → NetBoxError
`Unexpected token '<' is not valid JSON`.

**Fix**: `netboxGet()` strip leading slashes trước khi `new URL(relative, base)`.
Cả 2 style `/x/` và `x/` đều work.
Test: `http://host:8080/api/dcim/devices/?limit=3` (không còn `/api//`).

**Bug #2 (UX)**: `list_netbox_prefixes` chỉ hỗ trợ `site/status/limit` —
không answer được "subnet nào chứa IP 10.10.20.131" hay
"có tồn tại 10.10.20.0/24 trong NetBox không".

**Fix**: thêm 2 NetBox IPAM filter params:
- `contains=<IP>` — trả prefix(es) chứa IP đó
- `prefix=<CIDR>` — exact-match CIDR

Plumbed qua: `netboxClient.listNetboxPrefixes` type → `routes/netbox.ts`
query → `handlers.listNetboxPrefixesHandler` args → `prompts.ts` schema
advertise với example.
