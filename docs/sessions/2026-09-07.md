### 2026-09-07 09:57 -- Multi-vendor worker implementation: shipped (commit e4be0a4)

User asked to land the full rollout in one session. User-confirmed constraints:
- Lab containerlab images not needed (user has real prod Juniper + Arista + Cisco).
- Phase 1 uses shared env credentials (per-device is Phase 2).
- All 3 vendor backends + frontend vendor Select.

Shipped in a single commit (no per-vendor split because user explicitly asked for everything):
- `worker/netconsole_worker/backends/base.py` -- DeviceBackend ABC with 8 abstract methods + get_logs / connect_test defaults.
- `worker/netconsole_worker/backends/juniper.py` -- wraps existing junos_rest.py + ssh_client.py + all existing parsers. **Zero regression on lab Juniper** (the only behavioural change is moving the import inside each method, which is identical to the old code).
- `worker/netconsole_worker/backends/eos.py` -- Arista EOS eAPI JSON-RPC client. Parses `show interfaces` / `show ip arp` / `show mac address-table` / `show version` from eAPI JSON. Apply: `enable; configure terminal; <cmds>; end`. Rollback: `rollback rescue-config`.
- `worker/netconsole_worker/backends/iosxe.py` -- Cisco IOS-XE RESTCONF + SSH CLI fallback. RESTCONF first for interfaces + config + identity; SSH CLI first for ARP/MAC (YANG coverage is patchy). Apply uses `configure terminal` over SSH (NETCONF/ncclient is pre-staged but not wired because SSH is universal on IOS-XE). Rollback: `configure replace flash:pre.config force`.
- `worker/netconsole_worker/backends/nxos.py` -- Cisco NX-OS NX-API REST + NX-API CLI. RESTCONF-equivalent at `/api/mo/sys/...` for reads; `/ins` for `cli_conf` batches. Rollback: `rollback running-config checkpoint previous`.
- `worker/netconsole_worker/http_pool.py` -- vendor-agnostic httpx.Client pool (mirrors the existing JunosRESTPool shape so stats logging stays uniform).
- `worker/netconsole_worker/vendor.py` -- `detect_vendor(device)` reads `device.vendor` then falls back to model-keyword matching; `select_backend(device)` returns the right backend, falling back to Juniper for unknown vendors.
- `worker/netconsole_worker/config.py` -- 12 new env vars: `eos_api_{enabled,scheme,port,verify_tls,user,password}` + same for iosxe + same for nxos.
- `worker/netconsole_worker/tasks/registry.py` -- rewritten to dispatch via vendor selector. Each task is now ~3 lines: `_backend(device).<method>(...)`. Result shapes unchanged so the DB row writers and frontend don't care.
- `worker/netconsole_worker/tasks/managed_check.py` -- also dispatches via `select_backend(device).probe_identity(device)`.
- `worker/requirements.txt` -- +ncclient +textfsm +ntc-templates (pre-staged for the NETCONF path + textfsm parsers).
- `docker-compose.app.yml` -- 12 new env vars on worker (and on backend for symmetry, since the dispatcher in registry.py reads from env at import time).
- `frontend/src/pages/Devices/DeviceModal.tsx` -- vendor is now a `Select` (was `Input`) with 4 options (Juniper / Arista / Cisco IOS-XE / Cisco Nexus) + a per-vendor model `AutoComplete` that updates `shouldUpdate` triggers re-render of the model field when vendor changes.
