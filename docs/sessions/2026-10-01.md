# 2026-10-01

### 14:20 -- Fix bugs in NetBox sync: rack/position/IP all working

#### Bugs discovered and fixed

1. **Platform slug with dots** (`netbox.py`): `version="20.3R1.8"` → slug `juniper-20.3r1.8` → NetBox reject. Fixed with `re.sub(r'[^a-z0-9]', '-', ...)` to strip ALL non-alphanumeric chars.

2. **`face` required for `position`** (`_build_device_payload`): NetBox v4 requires `face` when `position` is set. Added `payload["face"] = "front"` (string, not integer `0`).

3. **`assigned_object_type` vs `interface`** (`assign_ip_to_interface`): NetBox v4 returns 200 for `{"interface": N}` but does NOT actually update the `assigned_object`. Must use `{"assigned_object_type": "dcim.interface", "assigned_object_id": N}`.

4. **IP conflict detection** (3-layer check): `assigned_object` null when old sync set `primary_ip4` without assigning to interface. Added:
   - Check `assigned_object.device.id`
   - Check `assigned_object_id` field
   - Check description `"Management IP for <name> — synced from NetConsole"` + device lookup
   - Skip ONLY if IP belongs to a DIFFERENT device; otherwise proceed.

5. **IP description ownership** (`_find_device_by_ip`): Used to detect if an IP belongs to a different device by parsing the description. But when the IP belongs to THIS device (even if not assigned to interface yet), still proceed to assign.

#### Result after fix

All 8 LAB devices now have in NetBox:
- Rack: V1-V6 (auto-created 42U racks)
- Position: correct U-positions (10, 10, 11, 9, 2, 4, 8, 10)
- Face: front
- primary_ip4: all 8 management IPs set correctly
- Platform: version-based (4.33.1.1F, 24.4R1.9, 15.2(20200924:215240), 20.3R1.8)
