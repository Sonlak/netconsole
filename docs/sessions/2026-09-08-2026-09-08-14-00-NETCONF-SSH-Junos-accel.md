### 14:xx -- Thử NETCONF SSH cho Juniper (nhanh hơn RESTCONF)

#### Context ban đầu
- User hỏi job commit config cho LAB-F2-AS-01 (10.10.20.221) mất 109s — có cách nào nhanh hơn không?
- Phân tích: RESTCONF đã batch 11 lệnh trong 1 load+1 commit = 2 HTTP POSTs. Không phải bottleneck.
- Nút thắt cổ chai là **cRPD commit latency** (68s cho commit) — giới hạn container simulation.
- Tuy nhiên, device LAB-F2-AS-01 là **Juniper ex9214** (Junos 24.4R1.9) — hardware thật, không phải cRPD.

#### Quyết định
Thử **NETCONF-over-SSH** thay RESTCONF. Lý do:
- Không có HTTP layer — kết nối trực tiếp TCP đến port 830
- Persistent SSH session cho load+commit (1 TCP handshake thay vì 2 HTTP POSTs)
- bypass paramiko (broken on OpenSSH 10 / Windows — gotcha #4) → dùng `sshpass + ssh -s netconf` CLI

#### Thay đổi code
- **worker/netconsole_worker/junos_netconf.py** (NEW) — JunosNETCONFPool dùng `sshpass + ssh -s netconf` cho NETCONF-over-SSH. Implements `apply_set_configuration` + `rollback_configuration` với cùng interface như junos_rest.
- **worker/netconsole_worker/backends/juniper.py** — update `apply_config` và `rollback_config` để thử NETCONF SSH **trước**, fallback RESTCONF.
- **worker/netconsole_worker/config.py** — thêm `junos_netconf_ssh_enabled` + `junos_netconf_ssh_port`.
- **worker/netconsole_worker/vendor.py** — thêm config fields + populate from settings.
- **worker/Dockerfile** — thêm `sshpass` vào worker image.
- **docker-compose.app.yml** — set `JUNOS_NETCONF_SSH_ENABLED=true` + `JUNOS_NETCONF_SSH_PORT=830`.

### 15:30 -- NETCONF SSH Junos hoạt động end-to-end (commit 212fbd9)

#### Vấn đề agent 14:xx để lại
- Module `junos_netconf.py` đã được tạo nhưng **không pass được hello exchange** từ code Python.
- Manual test qua bash heredoc thì OK, nhưng `subprocess.Popen` + `select()` trong code bị stuck ở hello.
- Người dùng yêu cầu "đọc Juniper docs rồi làm cho hoàn chỉnh" — đọc transcript cũ để hiểu context.

#### 3 bug tìm ra khi debug

1. **Missing `-T` flag trên ssh.** Khi stdin không phải TTY (subprocess.PIPE),
   OpenSSH skip NETCONF subsystem. Cần `-T` để force disable PTY mà vẫn invoke
   subsystem. Đã có trong test manual của agent cũ nhưng KHÔNG có trong code.

2. **Broken read loop.** `subprocess.Popen` + `select()` break ngay khi thấy
   `]]>]]>` đầu tiên (= terminator của device hello), nhưng bash subprocess
   thoát sớm sau khi heredoc xong — TRƯỚC khi SSH forward được RPC reply.
   → Chỉ trả về device hello, không có RPC reply.
   
   Fix: switch sang `subprocess.run(capture_output=True)`. Script bash
   block đúng cách (SSH giữ NETCONF channel open cho đến khi device reply),
   và `capture_output` đợi process xong mới trả về full hello + RPC reply.

3. **Sai RPC format.** `format="set"` + `<configuration-set>` bị reject
   với "expecting `<configuration>` or `<configuration-text>`".
   Đúng format Junos NETCONF: `format="text" action="set"` + `<configuration-set>`
   (giống RESTCONF đang dùng).

#### Code changes (commit 212fbd9)
- `worker/netconsole_worker/junos_netconf.py`: thêm `-T` flag, switch sang
  `subprocess.run`, fix RPC format, default timeout 90s split 30s load / 60s commit
  (cRPD commit có thể 60+ s — gotcha #15).
- `_parse_ok_error` đọc `<rpc-error>` TRƯỚC `<ok/>` — Junos đôi khi trả về
  cả hai trong cùng `<rpc-reply>` và code cũ nhầm success.
