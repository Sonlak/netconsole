## 16:14 – AI Assistant: chống bịa DHCP lease

### Vấn đề
User báo: hỏi "client nào đang được cấp DHCP" thì assistant trả
"Hiện không có client nào đang được cấp DHCP active trong hệ thống" — SAI.
API `/api/dhcp/leases` thật ra có 4 leases thật (10.1.201-204.0/24, MAC 00:50:79:66:68:05..0e).

### Phân tích (test bằng direct assistant call)
- LLM gọi tool đúng: `list_dhcp_leases({"state":"active","limit":50})`
- Tool result đúng: `{"total":0, "leases":[]}`  ← **đây mới là vấn đề**
- LLM trả text đúng theo tool result: "không có lease nào"

→ Không phải LLM bịa! LLM đang trung thực. Vấn đề ở **handler filter**:
- Tool enum cho state: `['active','expired','released','declined']`
- Data thật trong Kea: `stateLabel = 'default'` (= active), `'expired-reclaimed'`, `'released'`, `'declined'`
- Handler làm `stateLabel.toLowerCase() === wanted` → exact match
- LLM gọi `state="active"`, data có `stateLabel="default"` → **không khớp** → filter ra 0

### Fix
- `backend/src/services/assistant/handlers.ts::listDhcpLeasesHandler`:
  thêm alias map: `'active' → ['default','static']`, `'expired' → ['expired-reclaimed']`
- `backend/src/services/assistant/prompts.ts::listDhcpLeases.state`:
  thêm `'default'`, `'static'`, `'expired-reclaimed'` vào enum + mô tả rõ mapping

### Test sau deploy
Direct call `/api/assistant` với "DHCP leases dang active?":
- `tool_call`: `list_dhcp_leases({"state":"active"})`
- `tool_result`: 4 leases (đúng!)
- Assistant reply: bảng 4 dòng đầy đủ IP/MAC/Device/Port/VLAN.

### Commit
- `0d86ad1` — anti-hallucination rule (rule này đã có sẵn, LLM vẫn tuân thủ)
- `b367a88` — state alias mapping fix
