### 20:30 -- Uptime still stale: port 830 = OpenSSH, not Junos NETCONF subsystem

Root cause: device có config `netconf { ssh { port 830; } }` và `rest { http { port 8443; } }` trên cả 2 device, nhưng port scan cho thấy **port 830 trả về `SSH-2.0-OpenSSH_9.7`** (không phải Junos NETCONF subsystem). Port 8443 trả về `lighttpd/1.4.48` (cũng không phải Junos RESTCONF). Vậy cRPD lab không có NETCONF subsystem hoạt động.

**Tác động**: `probe_identity` thấy `netconf_open=True` (port 830 TCP open) nhưng `nc_fetch_system_uptime()` fail với "exec request failed on channel 0" → `uptimeSeconds` không bao giờ update → DB lưu giá trị cũ từ 2026-09-09.

**Fix**: Thêm SSH CLI fallback trong `probe_identity`:
- `junos_netconf.py`: thêm `fetch_system_uptime_cli()` — dùng sshpass+ssh subprocess chạy `show system uptime`
- `parsers/device_identity_rpc.py`: thêm `parse_system_uptime_cli()` — parse plain-text output, extract booted timestamp + tính uptime seconds
- `juniper.py::probe_identity`: khi NETCONF fail → gọi CLI fallback trên port 22
- Interval 5 phút giữ nguyên; mỗi lần CLI fallback chạy sẽ có 1 dòng trong auth.log (chấp nhận được cho lab)

Commit `4a239ef` đã push → CI deploy tự động.
