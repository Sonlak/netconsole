# Session 2026-10-17

## 11:20 – Kea DC↔DR hot-standby với auto-failback (triển khai toàn bộ)

### Ngữ cảnh
User chốt mô hình đơn giản: 1 Kea ở DC (active), 1 Kea ở DR (standby).
Bind :67 trên 10.10.20.20 (DC) và 10.10.20.30 (DR). Yêu cầu:
- Khi DC chết → DR tự serve (auto failover, Kea HA built-in)
- Khi DC hồi sinh → scheduler detect + auto switch về DC (auto failback)
- "Zero-downtime" = lease không bị ảnh hưởng, new client retry <30s

### Topology thực tế
- **DC**: VPS 100.102.133.86, public 42.119.165.109, container `kea-dc1` (172.31.0.10)
  - Bind `:67` trên host IP `10.10.20.20:67`
  - Peer URL → DR Tailscale: `http://100.105.166.18:8000/`
- **DR**: VPS 100.105.166.18, container `kea-dr1` (172.31.0.11)
  - Bind `:67` trên host IP `10.10.20.30:67` (only after promote)
  - Peer URL → DC Tailscale: `http://100.102.133.86:8000/`
- **Backend**: chạy ở DC, giao tiếp với DR qua Tailscale

### Auto-failback scheduler
- Polling mỗi 30s (env: `KEA_FAILBACK_CHECK_INTERVAL_SECONDS`)
- 4 stability gates (TẤT CẢ phải đạt):
  1. DC reachable (HTTP :8000)
  2. DC HA state = `hot-standby` (đã join + sync xong)
  3. DR đang active (`activeSite === 'DR'`)
  4. DC ổn định liên tục ≥ 5 phút (env: `KEA_FAILBACK_STABILITY_SECONDS`)
- Cooldown 1 giờ giữa 2 lần failback (env: `KEA_FAILBACK_COOLDOWN_SECONDS`)
- Toggle được qua API (env `KEA_AUTO_FAILBACK=true` để bật mặc định)
- In-memory state, restart = reset stability timer (an toàn)

### HA timing
```yaml
KEA_HEARTBEAT_DELAY_MS: 5000      # 5s heartbeat
KEA_MAX_RESPONSE_DELAY_MS: 10000  # 10s timeout window
KEA_MAX_ACK_DELAY_MS: 2000        # 2s ack delay
```

**Failover timeline:**
- T+0-15s: DC chết, DR heartbeat timeout
- T+15-30s: DR promote, bind :67 trên 10.10.20.30
- T+~5min: ops rebuild DC container
- T+~5min+5min (stability): scheduler trigger ha-switch-partner
- T+~10min: DC primary again (1-3s swap gap)
