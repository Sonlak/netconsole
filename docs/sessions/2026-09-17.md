# 2026-09-17

## 14:50 -- fix(fabric): LLDP Port ID bug — link labels showed description instead of interface name

**Symptom:** On `/fabric?floor=3`, the link between F3-AS-01 and F3-AS-02 was
labeled `link_to_sw_f3_as_01_ge-0/0/2` on the F3-AS-02 side (and `Gi0/3` on the
F3-AS-01 side).  Expected `gi1` / `GigabitEthernet1` (real interface name).

**Root cause:** `worker/backends/ios.py::_parse_ios_lldp` deliberately preferred
`Port Description` over `Port ID` when building `remotePort` (commit `fc022c6`
for the PortsPanel feature).  When the remote device (F3-AS-02) has the
`description` TLV set to a long string, the Fabric Topology was receiving the
description instead of the canonical interface name.

Secondary issue: `worker/backends/iosxe.py::get_lldp` ran `show lldp neighbors`
(brief) where the Port ID column bleeds into the description on long values,
even with the regex fix above.

**Fix:**
- `worker/backends/ios.py::_parse_ios_lldp` — `remotePort = Port ID`; new
  field `portDescription` exposed separately.
- `worker/backends/iosxe.py::get_lldp` — switch from `show lldp neighbors`
  to `show lldp neighbors detail`, reuse `_parse_ios_lldp` (separate fields).
- `worker/tasks/registry.py` — propagate `portDescription` into the merged
  interface row.
- `frontend/PortsPanel.tsx` — Description column prefers `portDescription`
  over `remotePort` so the link name display still works.
- `frontend/types/interfaces.ts` — add `portDescription?: string`.
- `worker/parsers/show_lldp_neighbors.py::parse_ios_lldp_neighbors` —
  fallback fixed-width column parser (no longer the main path, kept for
  the `show_lldp_neighbors` generic dispatcher).

**Verification:** Re-collected GET_INTERFACES for F3-AS-01 and F3-AS-02 via
`/api/interfaces/:id/collect`, then hit `/api/fabric?floor=3`:

  Before: `fromPort='link_to_sw_f3_as_01_ge-0/0/2'`, `toPort='Gi0/3'`
  After:  `fromPort='gi1'`, `toPort='Gi0/3'`  (correct)

All other floors (1, 4, 5 — Juniper + EOS + IOS links) show real interface
names (`ge-0/0/N`, `Ethernet1`, `Gi0/N`) — no regression.

**Deploy:** commit `95ed3d4` pushed, CI #408 + Deploy #395 succeeded.
