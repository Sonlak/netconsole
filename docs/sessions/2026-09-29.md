### 09:00 — feat(netbox): phase 1 device inventory sync

Add NetBox sync job — push NetConsole device inventory into NetBox on a
configurable interval. 14 files / 1535 LOC.

**Stack added**:
- Backend: `Device.netboxDeviceId / SyncedAt / SyncError` columns;
  `services/netboxSync.ts` scheduler (every N seconds, default 300);
  `POST /api/devices/:id/sync-netbox` and `/api/jobs/netbox-sync-all` routes.
- Worker: `clients/netbox.py` httpx wrapper (sites, manufacturers,
  device-types, devices, tags) with idempotent upsert keyed on
  `cf_netconsole_id`; `tasks/netbox_sync.py` with `NetboxSyncDeviceTask`
  and `NetboxSyncAllTask`.
- NetBox stack: `docker-compose.netbox.yml` (postgres + redis + netboxcommunity/netbox:v4)
  + `lab/netbox/init/01-init.py` (API token, custom field, source tag).

**Phase 1 surfaced 6 deploy-time traps** (all fixed in subsequent commits):

| # | Issue | Fix |
|---|---|---|
| 1 | `network netconsole declared as external` — both ymls defined the same network, netbox.yml marked external | Drop `external: true` |
| 2 | `Bind for 10.10.20.20:8001 failed: port is already allocated` (kea-primary uses it) | Use `8080:8080` instead |
| 3 | `failed to set up container networking: Address already in use` (netbox-netbox grabbed `.3`, backend's reserved IP) | Static IPs `.20/.21/.22` for netbox stack |
| 4 | `Models aren't loaded yet` from `showmigrations` — `SECRET_KEY` < 50 chars aborted Django.setup() | Pad to 64 chars |
| 5 | NetBox `POST /dcim/manufacturers/` → 400 `slug: required` | Derive slug from name |
| 6 | NetBox `POST /dcim/devices/` → 400 `primary_ip4 / oob_ip must be ID or dict, not string` | Defer IPAM linkage to Phase 2; store mgmt IP in `description` as `mgmt: <ip>` |
| 7 | Init script: `field.content_types.add()` → `AttributeError`. NetBox v4 renamed the M2M to `object_types` and the model to `extras.models.ObjectType` | New `_device_object_type()` helper tries `ObjectType` first, falls back to `ContentType` |
| 8 | `jobs.ts::complete` only persisted `netboxDeviceId` for `NETBOX_SYNC_DEVICE` (single) jobs; bulk ALL ran sync but the Device column stayed NULL forever | New branch iterates `result.results[]` and updates each Device row by `netconsoleId` |

**Final state (verified 10:09 UTC)**:
- NetBox running on http://42.119.165.109:8080 with 8 devices synced, site `LAB`, tag `source-netconsole`, custom field `netconsole_id` on dcim.device.
- All 8 NetConsole Devices have `netboxDeviceId = 1..8` and `netboxSyncedAt` populated.
- Auto-rollback untouched — every Deploy run was `success` even when the netbox step silently no-op'd (Compose never errored, the warning went to the GitHub step summary).
- One CI lint failure caught: unused `os` import in `tasks/netbox_sync.py` (fixed in `73a0e0b`).
- One bug found post-deploy: `'netbox-netbox' host DNS did not resolve from worker container`. Mitigation: switch to public IP (`42.119.165.109:8080`) for NETBOX_URL on both backend and worker. Underlying DNS issue still unexplained (might be a docker daemon quirk with containers attached via compose vs manual up).
