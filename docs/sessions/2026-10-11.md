### 17:35 -- Multi-action CROSS-INTERFACE (1 call, nhiều cổng)

User test trên LAB-F6-DS-01 (commit d1e4e0d đã deploy sáng nay 15:10):
- Yêu cầu: xoá + set VLAN + set desc trên cổng 8 VÀ 9 trong 1 lần commit.
- Multi-action chỉ target 1 interface / call (per design) → assistant chỉ queue được 1 cổng, phải queue 2 jobs riêng.
- User gõ "nhiều interface, nhiều task 1 lúc chứ ko phải 1 hay 2 gì?".

**Root cause**: schema multi-action `actions: [{action, vlan?|description?}, ...]` hoisted interface lên top-level. Cross-interface không có cách nào biểu diễn.

**Fix** (3 layer + tests):

- **Backend types**: `InterfaceSubAction` thêm optional `interface?: string` per subaction. `InterfaceActionPayload.interface` cũng optional (khi `actions` có per-subaction interface thì không cần top-level).

- **Backend parser** (`parseInterfaceActionPayload`):
  - Multi-action shape: 2 sub-shapes accepted
    - Cross-interface: không có top-level `interface`, mỗi subaction có riêng
    - Same-interface: top-level `interface` + subactions (subaction có thể override)
    - Mixed: top-level + một số subaction có riêng
  - Reject khi subaction không có interface VÀ không có top-level (worker sẽ raise clear error)
  - Legacy single-action vẫn require top-level interface

- **Backend route**: cập nhật 400 error message list 3 accepted shapes.

- **Backend handler**: 
  - Bỏ early check `device_name AND interface` (giờ interface optional)
  - Preview thêm `interfaces: string[]`, `interfaceCount: number`, `subActionSummary` per-interface

- **Worker `InterfaceActionTask`**:
  - Resolve interface cho từng subaction (per-subaction override top-level)
  - Cap 8 distinct interfaces / job (giữ summary readable, muốn nhiều hơn → queue thêm)
  - Group subactions theo interface (declaration order preserved)
  - Single-interface fast path: 1 `interface_action_multi` call (atomic 1 commit)
  - Cross-interface path: 1 `interface_action_multi` call PER interface group, sequential. Mỗi group vẫn atomic trên interface của nó; groups commit tuần tự. Cross-interface atomic chưa implement (1 commit cho 2 interface = worker phức tạp hơn nhiều, deferred).
  - **Bỏ contradiction check `delete-interface + set-X`**: ban đầu tao reject cái này nhưng thực tế user scenario CẦN nó (delete để clean, set lại vlan/desc mới). Trong Junos, declaration order = commit order, nên `delete interfaces X` rồi `set interfaces X unit 0 ... vlan members 201` chạy tuần tự → interface sạch + chỉ có VLAN/desc mới. Verified không gây error.

- **Prompt**:
  - Tool description: thêm cross-interface shape, ví dụ user scenario thật
  - System prompt: thêm section cross-interface
  - Confirmation card: group by interface, hiển thị "(N cổng)"

**Tests** (115 backend + 24 worker):
- backend/tests/services/interfaces.test.ts (+5): cross-interface full scenario, mixed top-level+per-subaction, reject subaction without interface (parser accepts; worker rejects), 17-subaction cap
- backend/tests/services/assistant/handlers.test.ts (+1): cross-interface preview shows interfaceCount=2, summary per-interface
- worker/tests/test_interface_task.py (NEW, 9 tests): cross-interface groups correctly, same-interface fast path, mixed top-level+per-subaction, contradictory shut+no-shut rejected, delete+set ALLOWED, 9-interface cap, missing interface rejected, sequential fallback, legacy single-action

**Trade-off accepted (chưa làm)**:
- Cross-interface single-commit: lý tưởng nhưng phức tạp (worker phải build 1 command list từ tất cả subactions của tất cả interfaces, xử lý partial failure). Cross-interface 1-commit-per-group là good enough cho v1; nếu user cần atomic 100% across interfaces thì mới optimize. Group-level atomic vẫn đảm bảo mỗi cổng nhất quán (không có half-state trên 1 cổng).
