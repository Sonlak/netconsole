## 08:15 -- fix(ports): Arista VLAN 1 + vQFX trunk members

**User:** "đọc cái chat này, vào kiểm tra cho tao thiết bị arista, phần port không lấy được thông tin vlan vậy? thêm phần juniper vqfx phần switch vlan cho port access bị mất rồi"

Two distinct read-path bugs on the Ports panel.

### Bug 1 — Arista EOS accessVlanId=1 silently dropped

`show interfaces switchport` JSON parser at
backend/src/services/eosApi.ts:362 and worker/.../backends/eos.py:1243
had `accessVlanId > 1` — meant to suppress the "default VLAN 1" UI noise,
but actually hid the access VLAN on every port sitting on VLAN 1.

Repro: F1-AS-01 Ethernet5..Ethernet8 are configured as
`switchport access vlan 1`. Device returns `accessVlanId=1` but the
parser dropped the field; the Ports panel showed them as
`Mode: access | VLAN: —`. Capture is now included (>= 1) so those
ports display "1" correctly.

Also dropped the special-case `trunkAllowedVlans !== "1"` so
single-VLAN trunks pass through cleanly.

### Bug 2 — Juniper vQFX trunk members overwritten with literal "all"

`apply_switching_modes` in worker/.../parsers/interface_set.py was
overwriting the per-VLAN list that `apply_vlan_membership` had just
built (e.g. "VLAN201 (201), VLAN202 (202), VLAN203 (203), VLAN204
(204), default (1)") with the literal string "all" whenever the
config had `vlan members all`. Result: F4-AS-01 xe-0/0/0,
F6-DS-01 xe-0/0/0, F6-DS-02 xe-0/0/0 — all trunk ports carrying
4-6 VLANs — displayed `accessVlan: all` and lost the actual member
list. Fix keeps the formatted list when present; falls back to the
literal "all" / "<expr>" only when no list was built (e.g. when
get-vlan-information RPC failed for that device).

## 09:15 -- fix(ports): Switch VLAN button hidden on every Junos access port

**User:** "thiết bị junos port nào đang access vlan vẫn không hiện nut switch vlan, rà lại cho tao đi"

The earlier b17ce69 fix surfaced this. With VLAN info now correctly
populated for Junos access ports (F4-AS-01 xe-0/0/1 → VLAN204, F6-DS-01
xe-0/0/10 → mgmt/10), the user clicked those rows expecting the "Switch
VLAN" action button — and it wasn't there.

### Root cause

`supportsAccessVlan` in frontend/src/features/ports/PortsPanel.tsx gated
the action button off the interface-name prefix:

    if (name.startsWith('xe-') || name.startsWith('et-') || name.includes('ae')) return false;

Every vQFX port starts with `xe-` (xe-0/0/0..47 on F4-AS-01 etc.), Juniper
MX/EX 40G/100G start with `et-`, and LAG bundles are `aeN`. So the
button never rendered on any Junos access port.

The defensive intent was to skip L3 uplinks (e.g. F6-DS-01 xe-0/0/3 with
IP 192.168.1.1). But `iface.address` is checked right after, which is
the actual L3 signal — the prefix check was redundant and wrong.

### Fix

Dropped the prefix exclusion. L3 ports are still blocked via `iface.address`
(`F6-DS-01 xe-0/0/3` 192.168.1.1, `F6-DS-02 xe-0/0/3` 192.168.1.5, etc.).
vQFX access ports now show the button:

| Port                       | Before | After |
|----------------------------|--------|-------|
| F4-AS-01 xe-0/0/1  (VLAN204) | hidden | ✓ shown |
| F6-DS-01 xe-0/0/10 (mgmt)    | hidden | ✓ shown |
| F2-AS-01 ge-0/0/2..4,6      | ✓       | ✓ shown |
| F1-AS-01 Ethernet2,3,5,6,7,8 | ✓       | ✓ shown |
| Any L3 routed port          | hidden | hidden (correct) |
