### 21:50 -- Fix 3 vấn đề assistant: smart-delete set-vlan + multi-action + delete-interface

User report trên live (commit 6ece2a3 đã deploy sáng nay):
1. Job 2c20367b (set VLAN 203 trên xe-0/0/7) **FAILED** với `error: unknown command: delete`
2. Assistant phải queue 2 job riêng cho `set-access-vlan` + `set-description` (user nói "sao không cấu hình 1 lần")
3. Assistant từ chối `delete interfaces xe-0/0/7` (user muốn reset interface)

**Root cause #1**: `worker/parsers/interface_set.py::commands_for_action` cho `set-access-vlan` LUÔN prepend `delete ... vlan members` line. Khi interface chưa có `vlan members` (vd đang ở trạng thái routed, mới chuyển sang access), `delete` bị Junos reject trong RESTCONF load. Sau đó fallback SSH CLI cũng fail vì operational mode không có `delete` command → "unknown command: delete".

**Root cause #2**: Backend `parseInterfaceActionPayload` và tool `queue_interface_action` chỉ chấp nhận 1 action / call. Worker `InterfaceActionTask` build commands cho 1 action → atomicity chỉ trong 1 lệnh, không gộp nhiều lệnh.

**Root cause #3**: Chưa có tool `delete-interface` cho Junos `delete interfaces <name>` (hoặc IOS-XE `no interface <name>`).

**Fix** (3 layer: backend+worker+prompt):

- **Fix A - Smart delete**: `commands_for_action('set-access-vlan', ...)` KHÔNG prepend `delete` nữa. Caller (`juniper.py::interface_action`) đọc config hiện tại qua `_read_interface_set()` (RESTCONF → NETCONF → SSH CLI fallback), nếu interface ĐÃ có `vlan members` thì mới prepend `delete`. Nếu chưa có, bare `set vlan members X` tạo entry mới (Junos không duplicate). Helper `has_vlan_members()` chuyển về `parsers/interface_set.py` cho testable.

- **Fix B - Multi-action atomic**:
  - Backend: `InterfaceActionPayload` mở rộng thành union `{action?, vlan?, description?}` legacy HOẶC `{actions: SubAction[]}` mới. `parseInterfaceActionPayload` validate cả 2 shape, max 16 subactions, reject contradictory (shut+no-shut, delete-interface + anything).
  - Worker `InterfaceActionTask._run_multi_action()`: build commands cho từng subaction, ghép thành 1 list, dispatch qua backend mới.
  - Backend mới `BaseBackend.interface_action_multi()` (default = sequential fallback, NOT atomic). Override:
    - **Junos**: 1 lần RESTCONF `<load-configuration>` + 1 lần `<commit-configuration>` (atomic trên thiết bị, ~17s RESTCONF vs ~24s sequential SSH).
    - **EOS eAPI**: 1 session `configure terminal` với tất cả sub-commands.
    - **IOS-XE**: 1 SSH session với `run_ssh_commands_session` để `configure terminal` mode persist.
    - IOS legacy + NX-OS: dùng default sequential fallback.
  - Tool schema: thêm `actions: [{action, vlan?, description?}, ...]` parameter. Confirmation card hiển thị summary kiểu "set VLAN 203 + set desc sonnx_test trên xe-0/0/7".
  - System prompt: nhấn mạnh "Ưu tiên multi-action hơn queue nhiều job riêng".

- **Fix C - delete-interface**:
  - Backend: thêm `'delete-interface'` vào `InterfaceAction` union.
  - Worker `commands_for_action`: Junos emit `delete interfaces <name>`, EOS emit `no interface <name>`, IOS-XE emit `no interface <name>`. Subif: delete cả physical interface (xóa hết units).
  - Multi-action reject delete-interface với subaction khác (mâu thuẫn, delete đã clear hết rồi).
  - Tool confirmation card: hiển thị warning emoji "⚠️ XÓA TOÀN BỘ cấu hình".

**Bonus fix (bonus bug tìm được)**:
- SSH CLI fallback ở juniper.py::interface_action trước đây chỉ trả 1 error (thường là SSH). Khi RESTCONF fail vì lý do khác, error bị nuốt mất — user chỉ thấy "unknown command: delete" (từ SSH). Fix: gộp cả `rest_error` lẫn `ssh_error` vào RuntimeError message ngăn cách bằng ` | `.
