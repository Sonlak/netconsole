# Session 2026-10-10

## 20:20 – AI Assistant: tối ưu end-to-end (real streaming + prompt rewrite + tool recovery + follow-up chips)

User phàn nàn "LLM vẫn đang quá gà, chưa có hiểu hết hệ thống, chưa tự phát triển
như 1 AI assistant hoàn chỉnh". Yêu cầu: optimize full Tier 3 (real streaming +
better prompt + proactive behavior + UI affordance).

### Ngữ cảnh & phân tích (đọc lại toàn bộ source)

Tao đọc kỹ 9 file chính của assistant module + session logs cũ:
`llmClient.ts` (wrapper), `prompts.ts` (system prompt + 39 tools), `handlers.ts`
(40+ handlers), `types.ts`, `statistics.ts` (17 stats), `routes/assistant.ts`
(SSE endpoint), `persistence.ts`, frontend `AssistantDrawer/MessageBubble/
ConfirmationCard`, `jobFollowUp.ts`.

Phát hiện các điểm "gà" thật:
1. **Streaming giả**: `routes/assistant.ts::callLlm` dùng non-streaming
   `chat.completions.create`, sau đó `streamTextInChunks` chunk 30 chars + 25ms
   delay. User phải đợi 1-3s cho full response mới thấy text. Wrapper `streamChat`
   đã viết sẵn nhưng KHÔNG ai dùng.
2. **Multi-step reasoning yếu**: LLM chain tool calls nhưng thiếu hướng dẫn
   explicit cho troubleshooting workflows.
3. **Không proactive**: Mỗi turn isolated, không gợi ý "Bạn có muốn X?".
4. **Tool descriptions sơ**: 30/39 tool không có examples.
5. **Self-awareness yếu**: Khi LLM gọi tool không tồn tại → throw exception
   thay vì gợi ý similar (giống pattern đã có cho stats).
6. **System prompt**: 1 monolithic block ~2000 tokens, không có few-shot examples.

### Thay đổi

**Phase 1: Real streaming** (commit sẽ push)
- `backend/src/services/assistant/llmClient.ts`: refactor `streamChat` thành
  AsyncGenerator yield `text` (real-time deltas) + `final` (assembled
  tool_calls + usage). Accumulator per-index cho tool_calls (OpenAI stream
  id/name/args qua nhiều chunks). Signal support để abort khi frontend disconnect.
- `backend/src/routes/assistant.ts`: thay `callLlm` + `streamTextInChunks`
  bằng `streamOneLlmTurn` thực sự stream. Bỏ synthetic chunking. AbortController
  wire vào `req.on('close')`. Recursion pattern giữ nguyên (READ tool execute
  inline → recurse; WRITE tool pause confirmation).
- `backend/tests/routes/assistant.test.ts`: helper `asStream` convert
  single-response sang AsyncIterable. Update 6 mock theo OpenAI streaming
  format (chunk 0: id+name, chunk N: args 8-char slices, final: finish_reason,
  cuối: usage). Test pass 8/8.

**Phase 2: System prompt rewrite** (chưa push)
- `backend/src/services/assistant/prompts.ts`: chia thành 10 sections có
  đánh số (1. Capabilities, 2. VÍ DỤ TỐT, 3. PROACTIVE, 4. WORKFLOW MẪU,
  5. DATA MAP, 6. Anti-hallucination, 7. WRITE flow, 8. Response style,
  9. Naming, 10. Permission).

- Thêm Examples: vào 5 critical tools: get_device, list_devices,
  lookup_mac, queue_interface_action, apply_config_dry_run, get_statistics.
- Update section 3 PROACTIVE: LLM gọi `suggest_followup` (tool mới) thay vì
  viết suggestion trong text.

**Phase 3: Tool self-recovery**
- `backend/src/routes/assistant.ts`: thêm `lookupToolOrSuggestion(name)` —
  trả null thay vì throw khi tool không tồn tại. Thêm `suggestToolNames(typo)`
  với 3 chiến thuật: substring match (10đ), token overlap (5đ), prefix match
  (2đ). Trả top 5 names. Frontend nhận `error` message kèm suggestion +
  `availableTools[]` list đầy đủ.
- Test mới: `emits tool_result with recovery suggestions when LLM calls
  a non-existent tool`. Verify suggest `get_device` khi LLM gọi
  `get_device_info`. 9/9 route tests pass.

**Phase 4: suggest_followup tool** (proactive UI affordance)
- `backend/src/services/assistant/types.ts`: thêm `'suggest_followup'` vào
  union, thêm `{ type: 'suggestions'; suggestions: string[] }` event.
- `backend/src/services/assistant/prompts.ts`: define tool với JSON schema
  (suggestions: array string, 1-3 items). Tool description giải thích "chips
  clickable, 10× more likely acted on than text question".
- `backend/src/services/assistant/handlers.ts`: `suggestFollowupHandler`
  validate, trim, slice(0, 3). Trả `{ suggestions: [...] }` preview.
- `backend/src/routes/assistant.ts`: trong tool execution loop, detect
  `name === 'suggest_followup'` → emit `suggestions` SSE event với
  filtered+sliced list (max 3).
- Frontend `api/assistant.ts`: thêm `suggestions` vào event union.
- Frontend `MessageBubble.tsx`: thêm `suggestions?: string[]` field,
  `onPickSuggestion` prop, render chips dưới text content. Click chip →
  gọi callback.
- Frontend `AssistantDrawer.tsx`: handle `onSuggestions` event, wire
  `onPickSuggestion={(s) => sendMessage(s)}`.
- Test mới trong `handlers.test.ts`: 3 test (valid, empty array, non-array).
