# Session 2026-10-20

## 10:30 – Fix dứt điểm: legitimate user bị khoá "Too many login attempts"

### Ngữ cảnh
User `sonnx` bị khóa "Too many login attempts, please try again after 15 minutes" sau khi
nhiều lần vào dashboard. Không phải do nhập sai pass nhiều lần — user chỉ nhập đúng 1 lần.
Root cause nằm ở in-memory `authRateLimit` (backend/src/middleware/rateLimit.ts).

### Nguyên nhân
- `app.use('/api/auth', authRateLimit, authRouter)` ở `index.ts:319` apply rate limiter
  vào TOÀN BỘ `/api/auth/*` (kể cả `/me`, `/refresh`, `/logout`).
- In-memory rate limit đếm CẢ LOGIN THÀNH CÔNG (200 OK cũng +1).
- Key generator lấy `req.body.username`, user `sonnx` → mọi login của user này cùng bucket.
- Max 10 / 15 min → sau 7–10 lần login (dù thành công) → 429.

Vì sao login nhiều lần? Frontend `useAuth` hook ở
`frontend/src/hooks/useAuth.ts:80-100`: khi `getCurrentUser()` fail → `clearAllAuth()` →
redirect /login → user nhập pass lại. Lặp lại nhiều lần trong session ngắn (15 min
access JWT, refresh token đôi lúc fail vì network blip / multi-tab race) → đủ 10 lần
trong 15 phút → khoá.

DB lockout ở `loginAttempt.ts` vẫn ok — chỉ tính failed attempts, không tính success.

### Thay đổi
1. `backend/src/middleware/rateLimit.ts`:
   - Thêm option `failuresOnly` cho `rateLimit()`. Khi true, response 2xx/3xx sẽ
     `res.on('finish')` decrement count → login thành công không tiêu budget.
   - Đổi `authRateLimit` sang `failuresOnly: true`, max 30 (tăng từ 10).
   - Key generator đổi prefix `login:user:` / `login:ip:` để không lẫn với các
     middleware khác.
2. `backend/src/index.ts:319`: bỏ `authRateLimit` khỏi global
   `app.use('/api/auth', ...)`. Comment giải thích lý do.
3. `backend/src/routes/auth.ts`:
   - Import `authRateLimit`.
   - Apply inline cho `POST /login` và `POST /mfa/verify` (HAI endpoint duy nhất
     cần credential-challenge gate).
   - Các endpoint khác (`/me`, `/refresh`, `/logout`, `/logout-all`, `/register`,
     `/users/*`, `/password`) chạy không rate-limit ngoài `authMiddleware` —
     như cũ trước khi có H11 hardening.

### Verify
- `npm run build` ở `backend/` → clean, no TS errors.
- Frontend không đổi.

### Notes
- DB-backed `loginAttempt.ts` lockout (5 lần sai liên tiếp) vẫn là authoritative
  gate — `authRateLimit` chỉ là fast filter để chặn DB hammering. Hai lớp này bổ
  sung cho nhau chứ không trùng.
- Vì sao không bump max lên rất cao (100+)? Cần giữ budget ở mức đủ chặn attacker
  trước khi DB lockout kịp react. 30 failed attempts / 15 min vẫn hơn 30 lần sức
  của 1 password-spray attack bình thường.
