**2. `ncclient` 0.7.1 bỏ `.data_xml` trên raw `dispatch()`**

`worker/netconsole_worker/ssh_client.py::_nc_data_to_ios_text` làm:

```python
root = getattr(rpc_reply_root, "data_xml", None) or rpc_reply_root
```

Nhưng ncclient >= 0.7.x, `conn.dispatch(rpc)` trả về `RPCReply` chỉ có
`.xml` (str của `<rpc-reply>`) — **không có** `.data_xml` lẫn `.data`.
→ `root` rơi về chính object `RPCReply` → `.findall()` nổ:

```
NETCONF error: 'RPCReply' object has no attribute 'findall'
```

Đã fix bằng helper mới `_nc_reply_root()` resolve theo thứ tự:
`.data` (element) → `.data_xml` (str) → `.xml` (str) → bản thân object.

**3. `switchport` subtree của IOS-XE nằm ở namespace khác + lồng sâu hơn**

Code cũ tìm leaf bằng `find("{native-ns}vlan")` và chỉ xét direct child:

```xml
<switchport xmlns="...Cisco-IOS-XE-native">
  <access xmlns="...Cisco-IOS-XE-switch"><vlan><vlan>400</vlan></vlan></access>
  <mode xmlns="...Cisco-IOS-XE-switch"><access/></mode>
</switchport>
```

→ in ra `switchport access vlan` (rỗng) + `switchport mode` (rỗng).
Đã fix bằng `_find_first_text()` (namespace-agnostic, recursive) và đọc
`<mode>` dạng presence container (child `<access/>` / `<trunk/>`).

### 21:00 -- Juniper QFX5120: route all read jobs through NETCONF SSH 830

**Vấn đề**: `NTMK-CORE-QFX5120` (10.1.240.250, Junos 23.4R2-S8.13) — `GET_CONFIG`
fail với `timed out`. Port scan từ VPS:

```
10.1.240.250:830  OPEN   (NETCONF over SSH)
10.1.240.250:8443 DROP   (RESTCONF — SYN bị Junos drop âm thầm)
```

`show system connections` trên thiết bị vẫn liệt kê `*.8443` là LISTEN, nhưng
Junos drop SYN đến cổng đó từ ngoài. Neighbor Junos cùng subnet (10.1.240.249)
trả REFUSED → chứng minh firewall/gateway không lọc 8443, chính Junos subsystem
loại nó. SSH local port-forward bị cấm (`sshd: refused local port forward`) nên
không bypass được.

**Quyết định**: dùng NETCONF SSH 830 làm đường đọc chính, RESTCONF chỉ là
fallback sau khi probe TCP thất bại.

#### Bug tìm được khi test NETCONF thật

1. **Multi-root XML**: raw NETCONF trả về `<hello>` + `<rpc-reply>` → `ET.fromstring`
   raise `junk after document element` → **mọi parser trả 0 dòng**. Fix: tách
   `<rpc-reply>` trước khi parse (`extract_rpc_reply`).
2. **Sai tên RPC**: `<get-arp-table/>` bị reject (`syntax error`), đúng là
   `<get-arp-table-information/>`. Tương tự `<get-ethernet-switching-table-information/>`,
   `<get-lldp-neighbors-information/>`, `<get-system-information/>`.
3. **`_parse_ok_error` quá hẹp**: chỉ whitelist `<configuration>` /
   `<interface-information>` / `<lldp-neighbors-information>` → ARP/MAC/VLAN reply
   bị đọc thành `Unknown NETCONF error`. Fix: accept mọi `<rpc-reply>` không có
   `<rpc-error>`.
4. **`xml_to_set_format` sinh config rác** với `<configuration-set>` (flat text):
   ra `set configuration-set "set version ..."`. Fix: ưu tiên flat text.
5. **LLDP tag sai**: Junos 23.x dùng `<lldp-local-port-id>` /
   `<lldp-remote-chassis-id>` (không phải `<lldp-local-port>` / `<lldp-chassis-id>`).
6. **`pool.borrow()` ngoài try block** trong `run_ssh_command` → exception
   (`Connection reset by peer`) nổi lên, làm fail cả job thay vì trả
   `sshOk: False`.
7. **RESTCONF 8443 DROP tốn 18s/job** → thêm TCP probe 1.5s trước khi gọi REST.
